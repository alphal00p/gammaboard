# MadGraph7 GammaBoard Integration

Thin Python process-evaluator wrapper for F2PY subprocess artifacts generated by
<https://github.com/MadGraphTeam/MadGraph7>.

The split is deliberately simple:

1. Generate and build the MadGraph artifact outside GammaBoard.
2. GammaBoard maps unit-hypercube points to phase-space momenta.
3. The wrapper imports the generated `matrix2py` module.
4. The wrapper returns matrix-element, phase-space weight, and/or weighted value
   through the GammaBoard process evaluator protocol.

## Install

```bash
cd integrations/madgraph
python -m venv .venv
. .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install .
```

## Runtime Flow

For the current `2 -> 2` evaluator, GammaBoard sends points in `[0, 1]^2`.
The wrapper maps each point to incoming and outgoing four-momenta, evaluates the
MadGraph matrix element, multiplies by the two-body phase-space weight, and
returns the selected components.

Available output components are:

- `value`: `matrix_element * phase_space_weight`
- `matrix_element`: raw matrix-element value returned by the generated artifact
- `phase_space_weight`: mapping weight, including flux when requested

Use a vector accumulator with matching component names.

## Matrix-Element Config

`matrix_element` always describes one generated F2PY subprocess module. There is
no backend selector.

```toml
[evaluator.args.matrix_element]
search_path = "integrations/madgraph/artifacts/ee_mumu/ee_mumu_f2py/SubProcesses/P1_epem_mupmum"
module = "matrix2py"
initialize_path = "integrations/madgraph/artifacts/ee_mumu/ee_mumu_f2py/Cards/param_card.dat"
function = "py_matrix_sum"
flavor = [1, 1, 2, 2]
helicities = "all_pm"
normalization = 4.0
```

`py_matrix_sum` is wrapper-side logic for flavor-dependent artifacts. It calls
generated `py_matrix(p, helicity, flavor)` for each configured helicity and
divides by `normalization`.

Direct `py_smatrix` calls are rejected because some generated wrappers omit the
flavor argument and can crash the worker. `py_get_value` and `py_smatrixhel`
remain callable for artifacts whose generated signatures are complete enough.

## Artifact Build Outline

See `examples/ee_mumu_f2py_subprocess.toml` for a concrete command sequence.
The important output is:

```text
SubProcesses/P1_epem_mupmum/matrix2py*.so
```

The runtime evaluator imports that module; it does not import MadGraph itself
and does not generate code on worker startup.
