Run: `gg_hhh_1_L_madnis`, ID 74. Completed PDF tasks: 223 (`pdf-2d-x-y`),
224 (`pdf-2d-x-z`), and 225 (`pdf-2d-y-z`). Investigation used read-only database

## What the plots contain

Each task evaluates a 128 × 128 plane at discrete coordinates `[0, 0]`, around
`[-369, -443, 278]`. The horizontal parameter `t` follows `u_vector`; the vertical
parameter `s` follows `v_vector`. Both range from -0.5 to +0.5, and the basis
vectors have length 10. Pixel `row * 128 + column` represents
`offset + t[column] * u_vector + s[row] * v_vector`. Both fields use this same
ordering in generation, persistence, and rendering; neither is transposed.

- **Reference-normalized integrand:** the magnitude of the evaluator's training
  projection, here `|Re f(p)|`, evaluated at the raster points with unit sampling
  weights. The displayed value is `log10(|Re f(p)| / I_ref)`. GammaLoop's
  parameterization Jacobian is included when returned; this run evaluates in
  momentum space. With this run's explicit vector target, `I_ref` is
  `hypot(5.4660399e-6, 1.892036e-6)`. Without an explicit target, the code uses the
  saved global absolute-integrand normalization when available, then the plane
  mean as a fallback. Run 74's saved global absolute-integrand normalization is
  absent. The target normalization is a reference scale, not a measurement of
  the integral of `|Re f|`.
- **Normalized PDF:** a separate call to the restored MadNIS sampler's `pdf()`
  at the same points. Displayed values are `log10(q(p) / mean_plane(q))`.
- **Sampling Accuracy:** by default `q(p) * I_ref / (|Re f(p)| * Z) - 1`, with
  `Z = 1` here; the alternative metric is the base-10 logarithm of that ratio.

The linear/zero-origin color controls act on these already logarithmic fields.
Independent default color ranges can make quite different magnitudes or slope
sizes look similar. The x-y integrand varies by only 5.6% across this small slice;
its stored PDF varies by 6.8%, both largely monotonic.

## Defect in the sampler adapter

`glnis_gammaboard_api/src/madnis_sampler.py::MadnisSampler.pdf` computes the
inverse spherical map, but previously built the flow input with the original
Cartesian `xs_continuous`, ignoring the returned `continuous` coordinates.
Thus it multiplied the inverse Jacobian by a density evaluated outside the
trained unit-cube coordinates. At the checked Cartesian points the flow returns
1; the displayed PDF there effectively follows the mapping Jacobian.

The fix passes the inverse-mapped `continuous` coordinates to the flow for both
discrete-coordinate placements (`first` and `last`). It retains the discrete
coordinate mask and applies the inverse Jacobian once. The user's existing
changes to the adapter checkout are preserved.

Replaying the old expression on all 16,384 points of each plane reproduces the
persisted PDF values with a maximum relative discrepancy of 2.0e-15. The correct
inverse coordinates lie near `[0.68, 0.40, 0.62]`, instead of Cartesian values
near `[-369, -443, 278]`.

| Plane | Stored PDF range | Corrected PDF range | Corrected/stored ratio |
| --- | --- | --- | --- |
| x-y | 4.6895e-11–5.0091e-11 | 1.1579e-13–1.4581e-13 | 0.002469–0.002911 |
| x-z | 4.7411e-11–4.9529e-11 | 1.2731e-13–1.4184e-13 | 0.002660–0.002891 |
| y-z | 4.7467e-11–4.9470e-11 | 1.2606e-13–1.4390e-13 | 0.002631–0.002937 |

The apparent rotation comes from different gradients in the data. Moving along
the vertical z direction from the first pixel, the reference decreases by about
2.24% on both z planes; the stored PDF increases by about 0.95%. After the fix,
the PDF decreases by 0.51% (x-z) and 0.46% (y-z). The corrected PDF need not
exactly reproduce the integrand: it is a learned approximation.

Sample generation uses `flow.sample(return_prob=True)` and the forward mapping,
not the faulty `pdf()` query. For 256 fresh points drawn from the saved checkpoint,
the corrected `q(p) * sampling_weight` differs from one by at most 2.92e-13.
This defect concerns diagnostic PDF queries, not that sampling-weight path.

## Applying the correction

Rebuild the Nix runtime in the sibling `glnis_gammaboard_api` checkout (`nix build`)
so `result/bin/python` includes the patched adapter. Redeploy gammaboard for the
export, parentheses formatting, and campaign-target changes. The saved diagnostic
arrays will not change merely by redeploying: regenerate the three PDF tasks from
the `madnis-train` snapshot. Retraining is unnecessary.

Regression tests cover inverse coordinates, discrete-coordinate masking and
placement, chunking, and Jacobian application. The adapter and mapping tests pass
(18 tests). Gammaboard's export was also checked directly against live run 74 in a
read-only connection: all seven completed tasks export and parse successfully.
